## TraceV1

Schema: `evals/schemas/trace-v1.schema.json`

```
Run
  provenance
  initial_state
  events:
    model.request / model.response
    tool.call / tool.result
    state.snapshot / state.delta
    delegate.start / delegate.end
    compression.start / compression.end
    diagnostic
    final.output
  final_state
  artifacts
  metrics
```

Every event has stable ids (`run_id:seq`), parent/span ids, order, and
redaction metadata (`secrets: fingerprint_only`).

## Operational canary

`.github/workflows/canary.yml` in this repo only:

- PR / push to main: TraceV1 unit tests + historical 3/3 from traces
- Daily 12:00 UTC / `workflow_dispatch`: resolve `origin/main` to a full
  SHA, run current canary, upload JSON/Markdown/traces as artifacts

`evals/provenance/canary-index.jsonl` is append-only:

`date, hermes_sha, harness_sha, fixture_digest, status`

Bulky traces stay in `results/` (gitignored) and workflow artifacts.
GHA canary uses `--no-index` so a scheduled job does not dirty main.
Local `python -m hermes_eval canary` appends the index.

Seeded with the v0.2 current-main row: `fab8479a…` =
`FIX_NOT_ON_THIS_SHA` × 3. `REGRESSION` is still illegal until a
known_good SHA is an ancestor of main.

## Prefix policy

See `reports/evals/prefix-policy.md`. Measured: ordinary suffix and tool
result append stay stable; compression, system-prompt change, and tool
schema change invalidate. Fallback / delegation / resume remain
unmeasured. Cache-eligible prefix ≠ provider cache hit.
